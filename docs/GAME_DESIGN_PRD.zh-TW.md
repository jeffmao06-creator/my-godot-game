# 訴訟之神之路｜遊戲設計文件與產品需求（GDD / PRD）

- 版本：v0.3，2026-10-23 修訂，可製作原型的設計草案
- 語言／市場：繁體中文／臺灣背景
- 開發方向：Godot 4、單人、精緻 2D 插畫、離線遊玩
- 遊戲名稱：《訴訟之神之路》。

本文整合玩法、數值、介面、內容與驗收規格。目標是讓開發者可以據此製作原型，並透過試玩調整經濟與節奏；本文不代表遊戲已完成實作或數值已經試玩驗證。

**規格標記**

- **原始需求**：玩家已指定的規則，應保留。
- **已確認調整**：主角開局可自由挑選一個金色與一個銀色特性，不使用隨機抽取。美術改以 PDF 概念圖的人物、材質與光色為準，不強制像素風；每日行動與指定事件加入小視窗過場，跳槽暫不製作過場。
- **建議規則／初值**：為了讓系統可實作而補上的定義、公式與數值，可在試玩後調整。
- **待確認**：原文存在多種解讀。本文會先指定原型採用的版本，最後集中列出問題，不讓開發停在規則空白處。

除另有標記，本文新增的費用、機率、消耗、薪資、成長分布與時間換算，均為**建議初值**，不是玩家已核定的數值。

## 1. 產品概念

### 1.1 一句話描述

你是一名剛完成律訓的臺北律師，從小型事務所的受僱律師開始，在有限的體力、時間與現金之間取捨，逐步成為合署律師、開業律師，最後經營遍及臺北、臺中、高雄的事務所。

### 1.2 核心樂趣

1. **接得越多，賺得越多，也越容易累垮。** 委任費先入帳，案件卻要背負半年。
2. **擴張可以分擔工作，也會增加固定支出。** 聘人和開分所必須同時考慮客源與現金流。
3. **職涯選擇改變收入模式。** 受僱換穩定薪資，合署用抽成換自主，開業以高成本換取全部委任費與經營權。
4. **養成形成不同的經營路線。** 高體力能扛案，高口才有助成交，高人氣帶來曝光與人才，高訴訟能力改善結果。

遊戲重心是疲勞管理、金錢管理及職涯經營。訴訟結果採數值結算，不製作法庭辯論、證據拼圖或逐句攻防玩法。

### 1.3 目標玩家與平台

- 喜歡經營、養成、資源分配及臺灣職場題材的玩家。
- 第一版以桌面電腦、滑鼠操作為主，支援常用鍵盤快捷鍵。
- 首發以繁體中文為必要內容；其他語言、手機、連線、控制器列為後續評估。

### 1.4 成功體驗

玩家能清楚理解「現在收下的錢，是未來半年工作量的交換」，能預見下一步的風險，並從適時拒案、培養能力、跳槽、聘人與擴張中獲得成就感。

## 3. 故事、職涯與里程碑

### 3.1 開場與教學

主角是臺北人，剛考上律師，已完成律訓。

開場依序呈現「考上律師 → 完成律訓 → 建立角色 → 進入職場」。考試與律訓以短篇敘事帶過，不另製作考試玩法，也不額外扣除未指定的律訓費用。

建立角色後：

- 金錢為 **NT$50,000**。
- 四項基礎能力皆為 **25**，再套用選擇的特性。
- 疲勞值的永久基礎上限為 **100**。
- 自由選擇角色外觀／性別，以及一個金色、一個銀色特性。
- 教學面試保證進入最小型事務所，避免尚未理解操作就因面試失敗反覆卡關。
- 第一件教學案件由公司分派；其一般晨間負荷從下一個早晨起計。

### 3.2 職涯狀態與轉換

```text
考上律師、完成律訓
         ↓
受僱律師 ───────────────→ 開業律師（準備 500 萬元）
    ↓ 同一事務所連續服務滿三年          ↓
可選擇成為合署律師                臺北本所經營
    ↓                                ↓ 各準備 600 萬元
合署律師 ───────────────→ 臺中／高雄分所
    └ 可保留身分跳槽
```

受僱、合署都可直接選擇開業，不強制先成為合署。成為合署是一個可以拒絕、稍後再接受的機會，不自動轉職。

### 3.3 三種身分

| 項目 | 受僱律師 | 合署律師 | 開業律師 |
|---|---|---|---|
| 主要收入 | 固定月薪、工作獎金 | 委任費的 70% | 委任費的 100% |
| 公司分派案件 | 有 | 不新增強制分派 | 無外部公司分案 |
| 獨立客戶諮詢事件 | 無 | 有 | 有 |
| 可跳槽 | 是 | 是，較難，保留合署身分 | 否 |
| 可招募／管理受僱律師 | 否 | 否 | 是 |
| 支付事務所租金及人事 | 否 | 不另付；以 30% 抽成表示 | 是 |
| 個人生活支出 | 有 | 有 | 有 |

**建議規則：** 合署不再保留固定受僱薪資；開業後沒有自動退回受僱的選項。這兩項必須在轉換確認視窗說明。

### 3.4 同所年資與跳槽

- 受僱在同一所連續待滿三年，觸發合署邀請。
- 受僱跳槽成功後，同所年資從新所到職日起重新累計；生涯總年資保留。
- 面試失敗不會失去現職。
- 已成為合署者跳槽成功後保留合署身分，不必再等三年。
- 受僱轉為合署時，原公司分派案件仍由主角完成，但不補發私人委任費；之後不再強制新增公司分案。
- 不論當時是受僱或合署，離開原所／直接開業時，尚未完成的原公司案件都留在原所，不轉成私人案件。
- 合署的私人案件在跳槽或開業時隨主角移轉；期限、準備度及已收款紀錄不變，不重收委任費，也不退還已扣的 30% 抽成。

### 3.5 經營目標與成功里程碑

里程碑依序包含：第一份工作、第一次勝訴、同所三年、成為合署、成立臺北本所、第一次聘人、第一次成功分案、成立臺中分所、成立高雄分所。

三地營運可以顯示「三地事務所」完成畫面及經營成績，之後繼續遊玩。原始需求未指定強制成功結局，因此不在達成三所時結束遊戲。

## 4. 核心循環與遊戲時間

### 4.1 核心循環

```text
查看現金、疲勞與案件負荷
    → 安排行動／接受或拒絕客戶
    → 取得收入、能力或案件準備度
    → 時段推進、處理事件
    → 隔日恢復疲勞、扣除持案負荷
    → 半年案件結算／每月財務結算
    → 選擇留任、跳槽、合署、聘人或擴張
```

### 4.2 曆法與時段〔建議規則〕

- 採簡化曆法：每月 **30 日**、每年 **360 日**。
- 顯示「生涯第 X 年／X 月／X 日」，不冒用真實公曆的月底與閏年。
- 半年 = **180 日**；三年 = **1,080 日**；兩個月 = **60 日**。
- 初版每天都可操作，不另設週末；「每週排程」一次最多排七日。
- 每日四個時段：**09:00、13:00、16:00、19:00**。
- 一次主要行動推進一個時段；19:00 行動後進入次日。
- 瀏覽介面、檢視員工、分案及存檔不推進時段；有明定費用者仍須支付。

### 4.3 操作節奏與每週排程〔建議必要功能〕

三年包含 4,320 個主要行動，必須提供重複行動的排程，避免職涯進展只剩點擊負擔。

- 玩家可設定未來七日各時段的動作、寫狀選案策略及是否每天吃早餐。
- 快轉仍逐時段／逐日執行同樣的金錢、疲勞、案件和事件規則。
- 預設遇到諮詢、媒體、錄取、合署邀請、員工過勞、案件結算或資金警告時暫停。
- 每項排程行動執行前先預覽影響；若預測會使金錢或疲勞歸零，暫停並要求玩家處理，不自動更換成有利選項。
- 玩家可隨時中止；不能以快轉跳過結局或延後欠款。
- 快轉前顯示現有案件將造成的晨間扣耗；保護機制只暫停模擬，不補資源、不豁免強制結算。

## 5. 能力、疲勞與角色

### 5.1 名詞必須分開

| 名稱 | 意義 | 範圍 |
|---|---|---|
| 訴訟能力 | 訴訟勝敗的主要能力 | 0–100 |
| 口才 | 委任轉換率、少量勝率加成 | 0–100 |
| 體力屬性 | 減少疲勞值的消耗 | 0–100 |
| 人氣 | 曝光、諮詢及開業後人才來源 | 0–100 |
| 疲勞值 | 每日可用精力；數值越高越有精神 | 0–當日上限 |

介面主資源沿用玩家指定的「疲勞值」，旁註「0 會累垮」；能力頁一律寫「體力屬性」，避免兩者混淆。

能力採整數；套用特性與成長後，最終能力皆限制在 0–100。四項能力總和的範圍為 0–400，特殊案以**套用特性後的最終值**判斷。

### 5.2 能力效果

| 能力 | 效果 |
|---|---|
| 訴訟能力 | 主要影響勝訴率，參與面試成功率判定 |
| 口才 | 小幅影響勝訴率，提高客戶願意委任的機率 |
| 體力屬性 | 每滿 10 點，疲勞消耗折扣增加 5% |
| 人氣 | 提高媒體與諮詢事件機率；開業後提高優質律師出現率 |

**原始限制：** 人氣對委任轉換率的加成只套用於受僱、開業身分；合署不享有此加成，但仍能藉人氣增加諮詢事件的出現率。

受僱沒有私人諮詢事件；其接洽客戶屬公司分案流程，成功後成為公司案件，不取得私人委任費。

### 5.3 疲勞消耗公式〔建議規則〕

```text
體力倍率 = 1 - 0.05 × floor(最終體力屬性 / 10)
特性倍率 = 所有適用的減耗倍率相乘
總消耗倍率 M = 體力倍率 × 特性倍率
實際消耗 = 四捨五入至小數第 2 位（基礎消耗 × M）
```

- 體力 25：倍率 0.90；體力 100：倍率 0.50。
- 頂級牛馬為 0.70，鐵人為 0.85，多面手為 0.90。
- 頂級牛馬＋鐵人、體力 25：`M = 0.90 × 0.70 × 0.85 = 0.5355`。
- 減耗涵蓋晨間持案負荷、工作及晚間行動；不折扣金錢支出，也不放大恢復量。
- 晨間負荷將全部案件合計後計算一次，不能逐案取整；否則每件 1 點的折扣會失效。
- 內部以固定小數精度儲存；介面顯示一至兩位小數，結局以儲存的實際值判定。

### 5.4 疲勞上限與每日恢復

```text
永久基礎上限 = 100 + 累積健身成長，最多 150
當日上限 = 永久基礎上限
         + 健康特性（有則 +10）
         + 前晚睡覺效果（有則 +20）
         + 當日早餐效果（有則 +10）
```

**建議解讀：** 健身的 150 封頂只限制永久基礎上限，健康、睡覺、早餐可以外加。依本版「主角一金一銀」的選角規則，主角沒有青銅健康特性，正常最高為 **180**；若未來允許主角取得健康，公式上界才是 190。體力屬性仍最多 100。NPC 的健康效果改為提高安全持案量，見第 11.4 節。

- 每日開始先回滿當日疲勞值，再扣晨間負荷。
- 睡覺效果只維持隔日，不連續疊加；早餐只維持當日。
- 早餐必須同時增加當前值及上限各 10；單加上限不補值會使當日效果失去意義。
- 健身只提升之後使用的永久上限，不在當晚額外補回疲勞。
- 無額外消耗時，疲勞值不隨真實時間流逝。

### 5.5 晨間結算順序〔建議規則〕

1. 推進日期；清除昨日早餐與到期睡覺效果，啟用前晚新取得的睡覺效果。
2. 結算今日到期案件，移除已結案件的持案負荷。
3. 更新應離職員工與案件移交；每月首日完成上月財務結算，先入帳收入，再一次結算應付成本。
4. 若金錢已歸零或低於零，立即進入破產結局，不繼續提供行動。
5. 計算今日上限並回滿疲勞值。
6. 主角持案及待分派案件每件提供 **1 點基礎負荷**，合計套用主角的 M 後扣除。
7. 疲勞值 ≤0，立即進入健康結局；不能用早餐救回已發生的結局。
8. 顯示 09:00 介面、當時段事件及早餐選項。

每個案件只由一名實際承辦者負擔一般晨間持案消耗，不會同時計在主角與受僱律師身上。待分派案件的責任另依第 11 節處理。

**日終補完順序：** 19:00 主角行動及結局檢查完成後，依員工當日最終負荷取得一次快照，更新疲勞狀態與連續日數，再執行一次 NPC 自動書狀、累計當日薪資／成本，最後推進日期。日終執行旗標須保存，讀檔不能多工作一次或多計一天薪資。

### 5.6 性別、外觀與其他角色

- 有男性、女性外觀；除美術與建模外，能力、特性機率、薪資、面試與事件完全相同。
- 一般角色有 0–2 個特性，且同一角色最多一個同色特性。
- 主角固定可自由選一金、一銀；一般角色的特性隨機，不可由玩家指定。
- NPC 也有四項能力，隨招募品質隨機生成，最終值不超過 100。

**人物身份與分層設計：** 每名角色保存穩定的 `AppearanceProfile`，包含身形／身體輪廓、臉型、膚色、眉眼鼻嘴、前後髮、髮色、鬍鬚、眼鏡／配件，以及衣服剪裁與色組。立繪、肖像及日後地圖人物讀取同一份身份資料與版本化素材引用，不再將「初階／資深 × 男女」當成四個固定身體，也不將員工肖像限制為十八張固定臉。

本版先以 PDF 概念圖品質製作人物插畫與動作過場，不把 v0.2 的低擬真 SVG 當成正式畫風。完整立繪、透明 PNG、可獨立替換的五官圖層及可綁定骨架是不同交付：未完成拆層或綁骨時，必須按實際狀態標示，不能把整張立繪稱作已完成的組裝骨架。

- 身形、臉型、髮型及服裝結構獨立於職級、能力及薪資；性別只影響玩家選擇的外觀表現。
- 膚色、髮色及衣服換色不能單獨當作不同角色的辨識度證明。
- 四十五名在職律師與三名新候選人須有結構差異與可辨識的組合；同批候選人不得只是換色、換名字或同臉換眼鏡。
- 資源數量以可交付圖層與相容姿勢計算，不以理論笛卡兒積冒稱已完成數萬張角色素材。現行畫風與交付界線見 `docs/art/ART_DIRECTION_v3.zh-TW.md`；v0.2 圖層樣本保留為歷史資料，不再強制使用其像素尺寸。

**NPC 特性分布建議：** 0／1／2 個特性的機率為 30%／50%／20%。抽色初始權重金 10、銀 30、銅 60；第二個特性排除已有顏色後重新正規化權重，再從該色等機率選一個。

## 6. 特性完整表

### 6.1 金色

| 特性 | 原始效果 | 原型中的明確定義 |
|---|---|---|
| 頂級牛馬 | 體力消耗減免三成，能扛更多案件 | 疲勞消耗 ×0.70，NPC 安全持案量同步提高 |
| 訴訟之神 | 勝訴機會提高 10% | 勝訴率 +10 個百分點 |

## 8. 隨機事件與客戶

### 8.1 事件共通規則〔建議〕

- 只在 09:00、13:00、16:00 進入時抽取一次；19:00 沒有這兩類事件。

- 接受事件會取代該時段的主要行動，推進一次時段。
- 09:00 事件出現時，可先吃一次早餐再回應；不因此改變事件內容或機率。

### 8.2 媒體邀請

所有職涯階段都可能收到「電視台邀請上節目」或「新聞台邀請受訪」。

```text
媒體機率 = min(25%, (1% + 人氣 × 0.05%) × 媒體特性倍率)
```

無特性時人氣 25 為 2.25%、人氣 100 為 6%；顏值頂天 ×2.5、人氣王 ×1.25，兩者可乘算。

接受後：基礎疲勞消耗 12、人氣 +1～3、推進時段。預設沒有通告費，避免另外創造未指定的主要收入來源。

### 8.3 諮詢事件

合署與開業可收到私人諮詢事件；受僱不會收到此類獨立接案事件。

```text
諮詢機率 = 5% + 人氣 × 0.15%
```

人氣 25 為 8.75%，人氣 100 為 20%。將媒體機率、諮詢機率、無事件機率作為一次互斥抽選；受僱的諮詢機率為零，不擠占媒體機率。

介面先顯示當事人、案由、委任費、半年期限、預估負荷與特殊案門檻，再讓玩家選擇「接洽」或「婉拒」。

- 接洽：基礎疲勞消耗 18，進行委任判定並推進一時段；成功或失敗都花掉這次時間。
- 委任成功：新增一件案件並收取一次委任費；晨間負荷自下個早晨起計。
- 洽談失敗：沒有委任費、不新增案件。
- 婉拒：不耗時、不耗疲勞；顧客離開，不反覆出現於同一時段。

### 8.4 委任轉換率〔建議〕

```text
委任率 = clamp(35% + 口才 × 0.4% + 適用的人氣加成, 5%, 95%)
人氣加成 = 人氣 × 0.05%（僅受僱／開業）；合署為 0
```

此公式與訴訟勝率獨立。受僱公司每月提供的潛在客戶，以此判定是否委任；不成功的名額不轉成主角案件、不影響固定月薪。第一件教學案件例外，保證成立。

## 9. 案件系統

### 9.1 顯示與資料

案件列表固定以 **「當事人－案由」** 呈現，例如「林小姐－離婚」「陳先生－詐欺」。

每案至少包含：唯一 ID、當事人、案型、所屬事務所、承辦律師、接案日、結案日、委任費與收款狀態、特殊門檻、準備度、隱藏結果亂數、進行中／勝訴／敗訴狀態。

案件另保存成立時的收入歸屬與分潤比例，供委任費及後續成功獎金使用，不隨轉職追溯改變。

### 9.2 案型與委任費

原始比例 50%＋20%＋10%＋10% 合計只有 90%。本文保留原有比例，將缺少的 10% 暫補「一般民事」；這項分類待確認。

| 案型 | 出現比例 | 委任費〔建議初值〕 | 特殊條件 |
|---|---|---|---|
| 詐欺 | 50% | 40,000 | 無 |
| 離婚 | 20% | 60,000 | 無 |
| 車禍 | 10% | 30,000 | 無 |
| 一般民事：租賃、勞資等 | 10%〔補足比例〕 | 40,000 | 無 |
| 特殊：毒品、商業爭議等 | 10% | 120,000 | 四項能力總和至少 300 |

案型抽選獨立於是否有資格承接，不能因能力不足就把特殊案的機率偷偷重分配。

### 9.3 特殊案件門檻〔待確認，原型先採此解讀〕

當接受委任者四項最終能力總和 **<300**，顯示指定文案：

> 能力值較低，承接此案可能性較低

繼續接洽則 **100% 委任失敗**，不收費、不新增案件，也不再擲普通委任率；已選接洽仍消耗該次行動與疲勞。

原文的「百分百失敗」本文解讀為委任失敗，不是成功接案後半年必定敗訴。因文案寫「可能性較低」卻實際為零，視窗另加系統註記「目前未達承接門檻，本次委任將失敗」，保留原句但不隱藏規則。

總和 **=300** 即通過門檻，之後仍需普通委任判定，不保證接案或勝訴。

主角直接接洽時檢查主角能力；開業後轉派或由員工接洽特殊案時，另檢查該名實際承辦者也達到 300，避免轉派繞過門檻。

### 9.4 半年期限

- 每案從接案／分派日起持續 180 日。
- 假設第 10 日成立，則第 190 日晨間結案；接案當天不立即扣晨間持案負荷。
- 寫狀、轉派、跳槽、開業、成立分所、承辦者離職，都不重設案件日期。
- 每案只結算一次，不因重讀、跨月或人員變更重複產生結果。

### 9.5 書狀與勝訴〔建議規則〕

- 每次寫狀使該案準備度 +1，上限 5；每點 +2 個百分點勝率，最多 +10 個百分點。
- 準備度屬案件資料，轉派後保留。
- 訴訟結果只在到期日結算，不另製作庭期操作。

```text
勝訴率 = clamp(
    25%
    + 承辦律師訴訟能力 × 0.4%
    + 承辦律師口才 × 0.05%
    + 準備度 × 2%
    + 勝訴特性加成
    - 案件難度扣減,
    5%, 95%)
```

普通案難度扣減暫為 0；特殊案扣減 10 個百分點。特殊案的高委任費與較難勝訴相互平衡。

例：訴訟 75、口才 50、準備度 5、有訴訟之神的普通案，勝率為 `25%＋30%＋2.5%＋10%＋10%=77.5%`。

案件建立時生成並保存隱藏的 `outcome_roll`；到期以當時承辦者能力與準備度計算勝率，再比較該亂數。案件結果不因重讀相同存檔而重新抽取，養成與書狀仍能改變勝率。

### 9.6 勝敗與收入

- 委任費在接案時收一次，不是每個月或結案時重收。
- 受僱案件的委任費歸原事務所；主角只拿薪資及已定義的工作獎金。
- 合署收 70%，老闆抽走 30%；開業的事務所收 100%。
- **建議規則：** 勝訴另給委任費 10% 的成功獎金，依相同分潤比例入帳；特殊案因費用較高，成功獎金亦較高。受僱案件的這筆客戶獎金歸公司，不直接給主角。
- 成功獎金沿用接案時保存的分潤；合署時成立的私人案，即使結案前已開業，這一案的獎金仍只收 70%。開業後新案才改收 100%。
- 敗訴不退已收委任費，也不額外扣款；勝敗紀錄仍列入生涯成績。其他賠償、稅務、保險不納入初版。
- 勝率不應成為唯一成長路線；主要收入仍來自委任費，成功獎金只是小幅增益。

### 10.3 面試成功率〔建議〕

```text
面試成功率 = clamp(
    30% + 訴訟能力 × 0.5% + 口才 × 0.3% + 人氣 × 0.1%
    - 規模難度 + 學霸加成 - 合署跳槽扣減,

```

規模難度依序為 0／10／20／30／40 個百分點；學霸加 20 個百分點，合署跳槽扣 15 個百分點。沒有其他硬性年資門檻；主角可自由嘗試跳槽。

### 10.4 月結與費用〔建議〕

- 個人生活費：每月 30,000 元，各身分皆支付。
- 每月首日結算上月：先發應得月薪與工作獎金，再扣生活費、租金、行政費及員工薪資。
- 薪資、生活費、租金及行政費以當月實際生效日數按 30 日比例累計，避免月底才跳槽卻領整月高薪，或月底聘人卻完全不用付薪。
- 職涯身分即刻切換，但當日日薪依日初生效的任職計算；新任職自次日影響日薪，同一人同日最多一份受僱日薪。
- 員工聘任次日到職，從到職日起可分案、工作並計薪；接受聘任當下先占用一個據點名額，避免超額預約。新據點租金及行政費從設立當日起累計。
- 比例費用先以整數分子累計（例如月薪 80,000 工作 15 日，記為 80,000×15），月結時每個合約／費用項目除以 30 後四捨五入一次；不可逐日日薪取整。完整 30 日必須正好等於約定月額，提前結清也使用相同算法。
- 轉為合署／開業前已累積的受僱薪資仍在原發薪日支付，不因換身分消失。
- 設立費、委任費與行動費用當下結算，不等月底。
- 初版不提供貸款、負餘額繼續營運、投資或被動利息。

### 10.5 開業與分所成本

| 項目 | 原始門檻／本文暫採的一次支出 | 月租〔建議〕 | 每月行政費〔建議〕 |
|---|---|---|---|
| 臺北本所 | 5,000,000 | 150,000 | 30,000 |
| 臺中分所 | 6,000,000 | 100,000 | 30,000 |
| 高雄分所 | 6,000,000 | 80,000 | 30,000 |

**待確認：** 原文的 500／600 萬可能是資本門檻，也可能是實際支出；原型先採一次性設立支出，涵蓋裝修、設備與成立所需費用，沒有可退款押金。

租金折扣只作用月租，人事折扣只作用員工薪資，不作用生活費、行政費、設立費或行動費。

**重要邊界：** 剛好有 500 萬而支付 500 萬，金錢變成 0，必須進破產結局；600 萬分所同理。不能為了開業流程偷偷豁免歸零規則。

確認視窗需顯示：

- 本次支出、支付後餘額、新增月固定成本。
- 三個月營運預備金建議值。
- 如果付款後為 0，明寫「支付後資金歸零，將立即觸發破產結局」，由玩家再次確認。
- 金額不足時禁用，不可借負數開業。

建議預備金只是風險提示，不另增加玩家原始指定以外的強制開業門檻。

### 10.6 財務頁的必要預測

顯示今日餘額、上月收支、本月已累積未支付成本、各據點成本、未結案件數、未來 30／90 日現金預測。

預設保守預測採「沒有新接案收入，只計已知應收與應付」，不得把機率客源列為保證收入。若提供平均情境，需另列並標示估計。

### 10.7 數值健全性範例

- 最小所一個完整月：薪資 60,000－生活費 30,000－每日早餐合計 3,000 = **淨增加 27,000**，尚未扣其他自選消費。
- 案型加權平均委任費：`50%×40,000＋20%×60,000＋10%×30,000＋10%×40,000＋10%×120,000 = 51,000`。
- 合署當月**成功新接**六件且符合上述案型平均：`6×51,000×70%=214,200` 收款；扣生活費後為 **184,200**，但新增案件仍要背負半年。
- 六件／月若長期維持，約有 36 件在手案件。這是穩態持案量，不是每月再收 36 件的委任費。
- 臺北本所聘三名月薪 100,000 的律師，完整月固定成本為 `150,000＋30,000＋300,000＋30,000=510,000`；三個月預備金為 **1,530,000**，不含自行選擇的消費。
- 三所租金合計 330,000、行政費 90,000；若四十五名律師平均月薪 100,000，再加生活費，完整月固定成本為 **4,950,000**。大型經營必須有持續客源，而非只看設立費。
- 中期營運情境：臺北一所五名一般律師，主角人氣 50、接洽者口才 50，假設全員未達特殊案門檻。每月委派的普通案成功期望為 `2×60%×57.5%×30×90%=18.63` 件；收款為 `2×60%×57.5%×30×(50%×40,000＋20%×60,000＋10%×30,000＋10%×40,000)=807,300`。五人均薪 100,000，加臺北租金、行政及生活費，月固定成本 **710,000**，差額 **97,300**。穩態約 112 件在手、每人約 22.4 件；不含主角親自諮詢、成功獎金與額外消費。
- 高成熟情境：三所各十五人、主角人氣 100、接洽者口才 75，委派期望每月新案 `9×80%×70%×30=151.2` 件；收款 **7,711,200**。若律師均薪 130,000，固定成本 **6,300,000**，差額 **1,411,200**。這是高人氣、高口才且特殊案資格與接案容量足夠的理想期望，不是保證收入；需在原型中量測是否過於寬鬆。

以上是算式檢查與情境示例，不代表玩家每月必然獲得這些客戶或收入。

## 11. 開業、人員與分所

### 11.1 容量與城市

- 先成立臺北本所，才可成立臺中或高雄分所；兩個分所的先後順序自由。
- 每個據點最多 **15 名受僱律師**，不含主角。
- 主角只存在一人，不在三個據點各複製一份；最多有 45 名受僱律師加主角。
- 同一城市不可重複設所，總計最多三所。
- 主角預設在臺北工作；檢視其他據點屬管理介面，不新增旅行耗時系統。

### 11.2 招募〔建議規則〕

「面試新員工」每次消耗一時段，提供三名候選人，最多聘一名。候選人在該次面試中固定；重開視窗不刷新名單，不另賣抽卡或重抽。

候選人建立時一次生成並保存完整 `AppearanceProfile`，與現有四十五人名單一起檢查結構重複與過度近似。重新排序、切換篩選、重開頁面與讀檔均不得改變外觀；同一人的招募卡、員工列、事件肖像及地圖人物必須一致。數值品質抽選不決定身體或臉型。

| 品質 | 四項最終能力總和範圍 | 建議月薪 |
|---|---|---|
| 初階 | 40–150 | 80,000 |
| 一般 | 151–250 | 100,000 |
| 資深 | 251–330 | 130,000 |
| 菁英 | 331–400 | 160,000 |

先按下列人氣機率抽品質，再生成符合該品質「套用特性、每項封頂後總和範圍」的能力及特性；若超出區間，只重新生成符合條件的能力，不能因生成順序而改變品質機率。初階的 40 分下限是招募市場的最低入池條件，不符合者不生成為候選人。品質不同不保證某個指定特性。

開業主角人氣影響每名候選人的品質機率：

```text
菁英機率 = 2% + 人氣 × 0.15%
資深機率 = 15% + 人氣 × 0.1%
一般機率 = 45%
初階機率 = 其餘機率
```

聘任前顯示四項能力、特性、生效／未生效效果、月薪、所屬據點、到職日與安全持案量。選擇滿員據點時禁用聘任；聘人本身不另收獵頭費，薪資從次日到職起累計。

### 11.3 分案與書狀

- 開業後可把自有案件分派給旗下律師；每案同時只能有一名承辦者。
- 分案操作不推進時段、不重收費、不重設期限、不清除準備度。
- 分派當下立刻更新列表；其晨間負荷從下一個早晨起由新承辦者承擔。
- 特殊案的接任者必須滿足四項能力總和至少 300。
- 介面顯示分派前後的持案量、安全持案量與過勞警告，並提供「依負荷自動分派」功能。
- **NPC 工作補完規則：** 每日日終快照判定為正常狀態者，自動處理最多三份書狀，優先準備度最低、其次最早到期的案件，每份 +1；疲勞狀態降為一份。日終只執行一次，每案準備度仍上限 5，不增加委任費或縮短期限。
- 主角的「寫書狀」選項只處理本人承辦案件，不額外替全所瞬間加成。

### 11.4 NPC 過勞與離職〔建議可實作定義〕

NPC 不套用主角「疲勞值歸零即遊戲結束」規則，使用持案容量與連續疲勞日數。

```text
NPC 上限倍率 = 1.10（有健康特性）；否則為 1
NPC 安全持案量 = floor(27 × NPC 上限倍率 / 該 NPC 的總消耗倍率 M)
在手件數 > 安全持案量 → 疲勞狀態
連續疲勞 60 日 → 離職
忠誠 → 改為連續疲勞 90 日才離職
```

無減耗特性、體力 25 的安全持案量為 30；體力 100 時為 54。以此符合「約三十件、受體力影響」的原意。

- 每日日終只取得一次最終負荷快照，再更新疲勞狀態與連續日數；同一日不重複計數。
- 當日日終快照回到安全持案量以內，才解除疲勞並將連續日數歸零。日中分案只更新負荷預覽，不改寫計時，不能靠暫時移出一案再放回來刷掉疲勞。
- UI 顯示「疲勞第 X／60 日」及第 30、50 日提示；忠誠改顯示 90 日期限。
- 滿期限後，下一個晨間離職；月底及跨年都不能重設計時。
- 初版不額外加入隨機離職，避免無從理解的流失；忠誠延長過勞耐受作為「較不易離職」的具體效果。

### 11.5 離職、待分派案件與解僱

- 離職案件回事務所待分派清單，不消失、不重新收費、不瞬間全部變成主角的直接承辦案件。
- 從移交當日晨間起，待分派案件每件仍對主角產生 1 點基礎行政負荷，套用主角減耗後扣除；避免靠永遠不分派免費消除負荷。
- 分派給合格承辦者後，次日起不再產生主角待分派負荷；同一早晨不重扣或退款。
- 若到期仍沒有承辦者，該案自動敗訴，明確顯示「未配置承辦律師」，不以不存在的承辦者能力擲勝率。
- 已累積的員工薪資不因離職消失，仍列入下次月結。
- **建議管理功能：** 可主動終止雇用，立即支付一次月薪作為遊戲內補償金，另外結清至終止當日的應付薪資；案子按同樣規則移交。已結清的薪資分子與付款旗標一併更新，不能到月底重付。自然離職則仍在原月結日支付。這是成本管理選項，不另模擬完整勞動法程序。

### 11.6 分所客源與委派接洽〔新增建議機制〕

只有主角每天三個事件入口，無法支撐四十五名律師。因此分所需要實際客源與接洽能力，而非只有租金。

建議所有自有據點都能讓當地受僱律師接洽新客戶；這是 NPC 在自己的時間內工作，不消耗主角的一個時段。

- 未配置受僱律師的據點沒有委派接洽；主角仍可收到原本的主動諮詢事件。
- 當地每日接洽名額：`min(3, 1 + floor(當地受僱律師數 / 5))`。
- 每個名額有 `40% + 主角人氣×0.4%` 的機率出現潛在客戶，上限 80%。
- 由玩家指定的當地接洽律師，以自己的口才及主角開業品牌的人氣加成判定委任率。
- 特殊案檢查接洽者及預定承辦者均達門檻；費用入全所資金池，只收一次。
- 預設自動接案關閉，先將候選案呈報玩家。開啟後可設定案型、最低費用及每名律師負荷上限。
- 自動策略只在有合格承辦者、且分派後不超過設定上限時接案；沒有容量就婉拒並記錄，不放進無限待分派池。
- 主角事件與委派接洽是不同來源，各有唯一客戶／案件 ID，不可對同一客戶收兩次費。
- 每日晨間負荷結算完成後再執行委派接洽；因此新案同樣從次日開始產生持案負荷。

此機制的機率與容量須重點試玩。若刪除此機制，必須另設能支撐三地規模的客源，而不能只保留擴張支出。

## 12. 失敗結局與資源歸零

### 12.1 健康亮起紅燈結局

條件：主角疲勞值 **≤0**，無論來自晨間持案或行動消耗。

指定文案：

> 你太累了，有一天你工作到昏倒，醫生說你再繼續下去可能會有生命危險，你選擇退休。

結局名稱：**健康亮起紅燈結局**。

### 12.2 破產結局

條件：一筆已確認交易或強制結算後，金錢 **≤0**。不足支付的自選消費不可執行；強制成本可能使餘額低於零，仍立刻結束。

指定文案：

> 你破產了，律師這行你做不來的，你決定回家啃老。

結局名稱：**破產結局**。

### 12.3 結局判定〔建議規則〕

- 每筆主行動將費用、疲勞及效果作為一個原子結算步驟，結束後立即檢查，不能先切到隔日補滿再判定。
- 同一個原子步驟若兩者同時 ≤0，優先顯示健康結局，紀錄保留兩個原因；不同步驟則先觸發者立即結束。
- 結局後停止收入、時間與員工模擬，提供「讀取存檔／重新開始／返回標題」。
- 不強制覆寫原存檔，不讓結局判定後繼續點擊取得資源。

## 14. 存檔與讀檔

### 14.1 二十個存檔位

- 提供 **20 個可選手動槽位**，編號 01–20。
- 第一版不強制自動存檔；若後續增加，需指定既有槽位且先獲玩家設定，不能偷偷覆寫手動進度。
- 存檔摘要：角色名稱／外觀、生涯日期、時段、身分、現金、疲勞、據點數、遊玩時間。
- 支援覆寫確認、刪除確認及空槽顯示。
- 使用 Godot `user://saves/`；不把玩家存檔寫進專案資源目錄。

### 14.2 必須保存的狀態

1. 版本、日期、時段、教學與職涯旗標。
2. 金錢、交易流水、已累積但未發放薪資、未付費用、已結算月份。
3. 主角／NPC 的基礎能力、特性、最終能力所需資料、唯一 ID，以及完整 `AppearanceProfile`、外觀資料版本與素材庫版本；不可只存亂數種子或角色基底編號。
4. 當前疲勞、永久上限、早餐旗標、睡覺效果期限。
5. 任職事務所、加入日期、同所年資、合署資格。
6. 所有案件的日期、承辦關係、準備度、收款旗標、結果與隱藏亂數。
7. 據點、人員、薪資、過勞狀態與連續日數、待分派池。
8. 當時段已抽事件、回應狀態、面試候選名單。
9. 系統亂數狀態、每週排程與自動接案政策。
10. 遊戲進行／結局狀態、生涯成績。

### 14.3 正確性

- 只在穩定決策點存讀檔，禁止在交易／結算執行到一半時保存半套狀態。
- 先寫暫存檔、成功後替換正式檔，並保留上次有效備份；備份不增加可選槽位數。
- 讀檔還原狀態，不重新執行該日／該月結算。

### 16.3 技術約束

- 金錢用整數；疲勞用固定小數精度。機率與折扣只由單一共用計算入口產生。
- 調整薪資、費用、機率、特性及事件內容應改資料設定，不散落在 UI 程式中。
- 時間只透過 TimeSystem 推進；關閉視窗、存檔或重讀不增加一天。
- 同一案件收費、同一月份結帳及同一事件回應具唯一識別與執行旗標。
- 預覽與真正結算使用同一套計算，避免 UI 說安全、執行後卻破產。
- 初版目標量為主角＋45 名律師及約 2,500 件在手案件；列表分頁／虛擬化，日結分批處理，不卡住介面。
- 圖形介面需實際檢查；Godot headless 測試可驗證結算與存檔，但不能替代插畫畫面、動作連續性、點擊與文字可讀性驗收。

## 19. 平衡風險與試玩觀察

### 19.1 已知風險

| 風險 | 原因 | 保留規則下的處理方向 |
|---|---|---|
| 能力數週即接近封頂 | 每次 +1～3／+1～5，相對 100 上限很快 | 先保留增幅，量測達 300 與滿屬性的天數，不把能力 300 設成多年後才達成的劇情門檻 |
| 三年等待太冗長 | 同所 1,080 日、4,320 主行動 | 七日排程、事件暫停與里程碑；若仍過慢，再討論修改曆法／年資條件 |
| 接案即收費，先富後累 | 一次收費、半年負荷 | 明示在手義務、次日負荷及保守現金流，不把現金視為已完成利潤 |
| 沒有真正的拒案壓力 | 若疲勞過於寬鬆或委派沒有限制 | 檢查高持案時的消耗、NPC 容量及客源，不偷加未告知的扣耗 |
| 招募只帶成本或毫無風險 | 客源太少／員工過勞處罰不明 | 聯合調整客源、薪資、安全量及提示，保持「適量聘人」有用 |
| 分所成為負資產 | 開所只增加成本，主角事件數不增加 | 委派接洽帶來當地客源，觀察各據點回收期 |
| 牛馬＋鐵人成為唯一選擇 | 可自選且兩者乘算減耗很強 | 比較商人、訴訟、人氣路線的資金及風險；不暗中削弱已寫明特性 |
| 存檔刷亂數或重複領薪 | 狀態與事件旗標不完整 | 固定結果、獨立亂數、唯一收款與月結紀錄 |

### 19.2 試玩至少記錄

- 首次理解疲勞、收費與半年負荷所需時間。
- 達能力總和 300、首次跳槽、同所三年、合署、開業及各分所的遊戲日期與實際操作時間。
- 每日平均剩餘疲勞、在手量、拒案率、員工過勞率與離職原因。
- 各階段月現金流、第一次破產／退休原因、是否在執行前看見預警。
- 各特性組合的選擇率與經營差異。
- 排程使用率與暫停原因；若大部分時間都在無意義地重複相同行動，回頭調整節奏。
